# Level Balance Document - Level 1~100 (v2.3 - 화살표 수 완화)

## 1. 난이도 설계 철학

### 1.1 목표
- Level 1~100까지 점진적이고 자연스러운 난이도 상승
- 플레이어가 새로운 메커니즘을 하나씩 학습할 수 있는 구조
- **v2 변경**: 초반부터 적극적인 화살표 투입, 메커니즘 조기 도입으로 전체 난이도 상향

### 1.2 고정 파라미터

| 파라미터 | 값 | 이유 |
|----------|-----|------|
| targetDensity | **0.88 ~ 0.92** | 맵이 항상 가득 찬 느낌 유지. 초반~후반 모두 동일 (v2.1: 0.02 완화) |
| fillerEnabled | false | Filler 없이 Main/Miss/Decoy 화살표만으로 밀도 달성 |

### 1.3 난이도 조절 파라미터

| 파라미터 | 범위 | 난이도 기여 | 설명 |
|----------|------|------------|------|
| gridSize | 4~20 | ★★★★★ | 그리드 크기. 클수록 화살표 수 증가, 공간 복잡도 상승 |
| laneCount | 2~6 | ★★★ | 풍선 레인 수. 많을수록 색상 매칭 경우의 수 증가 |
| balloonsPerLane | 1~8 | ★★★★ | 레인당 풍선 수. 많을수록 탈출 순서 파악이 어려움 |
| missArrowCount | 0~6 | ★★★ | 풍선과 매칭 안 되는 화살표. 노이즈 역할 (v2.3: -1 완화) |
| decoyArrowCount | 0~3 | ★★ | 함정 화살표. 탈출해도 풍선 안 터뜨림 (v2.3: -1 완화) |
| minBlockLength | 2 | ★★ | 최소 화살표 길이 (전체 고정) |
| maxBlockLength | 3~14 | ★★★ | 최대 화살표 길이. 길수록 서로 더 많이 막힘 (v2.2: -2 완화) |
| bendingEnabled | T/F | ★★★ | 꺽이는 화살표 활성화. 탈출 경로 예측 난이도 상승 |
| bendingChance | 0~1.0 | ★★ | 꺽이는 화살표 비율 |
### 1.4 난이도 점수 산정 공식 (100점 만점)

밀도가 고정이므로 난이도 점수에서 밀도 항목 제거. 나머지 파라미터로 재분배:

```
DifficultyScore =
    GridScore       (0~35)  : (gridSize - 4) / 16 * 35
  + BalloonScore    (0~30)  : totalBalloons / 48 * 30
  + MissRatio       (0~15)  : missArrows / max(totalArrows, 1) * 60
  + DecoyScore      (0~8)   : decoyArrows * 2
  + BendingScore    (0~12)  : bendingChance * 12
```

여기서:
- `totalBalloons = laneCount * balloonsPerLane`
- `totalArrows = totalBalloons + missArrows + decoyArrows`

### 2.1 구간 정의 (v2)

## 3. 난이도 곡선 설계 근거

### 3.1 v2 변경 근거

1. **초반 활성화**: Level 2부터 화살표 3개 투입. "쉽지만 할 것이 있는" 느낌 제공
2. **빠른 메커니즘 도입**: 3레인(L10), Bending(L15), 4레인(L21), Decoy(L25), 5레인(L31), 6레인(L40)으로 모든 메커니즘을 L40까지 도입 완료
3. **중반 집중**: L21~55에서 메커니즘 조합의 난이도를 집중 상승
4. **후반 안정**: L56~100은 그리드 크기와 파라미터 미세 조정으로 점진적 상승
### 3.2 파라미터별 도입 시점 (v2)

### 3.4 밀도 고정 근거

- 밀도 50~70%의 맵은 빈 공간이 많아 "비어보이는" 느낌 -> 퍼즐 완성도 저하
- 밀도 90~95%는 화살표가 빵빵하게 채워져 "풀어야 할 문제"가 많다는 시각적 인상
- 초반 레벨(gridSize 4~5)도 90% 밀도면 화살표 3~5개로 충분히 쉰움
- 난이도 차별화는 gridSize/laneCount/miss/decoy/bending 조합으로 충분

## 4. 현재 파라미터로 구현 가능 여부

### 4.1 결론: **가능합니다**

현재 `GeneratorConfig`의 모든 파라미터를 레벨별로 지정하면 제안된 난이도 곡선을 구현할 수 있습니다.

### 4.2 파라미터 매핑

| 난이도 요소 | 대응 파라미터 | 제어 가능 여부 |
|------------|-------------|--------------|
| 그리드 규모 | `gridSize` | O - 직접 지정 |
| 풍선 복잡도 | `laneCount`, `balloonsPerLane` | O - 직접 지정 |
| 노이즈/함정 | `missArrowCount`, `decoyArrowCount` | O - 직접 지정 |
| 화살표 복잡도 | `minBlockLength`, `maxBlockLength` | O - 직접 지정 |
| 공간 밀도 | `targetDensity` | O - 0.88~0.92 고정 |
| 경로 복잡도 | `bendingEnabled`, `bendingChance` | O - 직접 지정 |

### 4.3 추가 고려사항

- **Filler**: `fillerEnabled=false`. 밀도 90%+는 Main/Miss/Decoy 화살표로 달성.
- **Branching**: `branchingMode`는 화살표 배치 다양성을 증가시킴. Level 30+ 권장.
- **색상 수**: 현재 6색(R,G,Y,P,B,O) 고정. 초반에는 2~3색만 사용되도록 laneCount로 간접 제어.

## 8. 구현 방법

### 8.1 레벨별 파라미터를 GeneratorConfig로 변환

각 레벨의 파라미터를 `GeneratorConfig`로 변환하여 `LevelGenerator.GenerateLevel(config)`에 전달하면 됩니다.

```csharp
// 예시: Level 25용 Config (Decoy 도입 레벨)
var config = new LevelGenerator.GeneratorConfig
{
    gridSize = 9,
    laneCount = 4,
    balloonsPerLane = 4,
    missArrowCount = 2,
    decoyArrowCount = 1,
    minBlockLength = 3,
    maxBlockLength = 8,
    targetDensity = 0.88f,
    bendingEnabled = true,
    bendingChance = 0.8f,
    fillerEnabled = false,
    branchingMode = false
};

var levelData = LevelGenerator.GenerateLevel(config);
```

### 8.2 AutoParams vs Manual Params

- **AutoParams**: `CalculateAutoParams(gridSize)` - gridSize 하나로 자동 계산. 빠른 프로토타이핑용.
- **Manual Params**: 이 문서의 레벨별 파라미터를 직접 지정. 정밀한 난이도 제어용.

**권장**: 이 문서의 파라미터를 기반으로 레벨별 Config 테이블(`LevelConfigTable.json`)을 사용.

### 8.3 생성 실패 대비

`GenerateLevel()`은 최대 50회(배치 생성 시 200회) 시도 후 실패할 수 있음. 배치 생성 시스템에서 4단계 완화 전략 적용:
1. gridSize +1
2. maxBlockLength -1 or -2
3. missArrowCount -1
4. targetDensity -0.05

**v2.3 참고**: 원본 파라미터 자체가 완화되어 있어 실패 확률이 낮음.

## 9. 플레이테스트 권장사항

1. **Phase 전환점** (Level 9, 20, 35, 55, 80) 에서 체감 난이도 급변 여부 확인
2. **새 메커니즘 도입 레벨** (9, 10, 15, 21, 32, 30, 40) 에서 학습 곡선 확인
3. **클리어율 목표**:
   - Phase 1: 90%+ (첨 시도 클리어)
   - Phase 2: 75%+ (1~2회 시도)
   - Phase 3: 55%+ (2~3회 시도)
   - Phase 4: 40%+ (3~5회 시도)
   - Phase 5: 25%+ (5~10회 시도)
   - Phase 6: 15%+ (10회+ 시도)
4. **부스터 사용률**: Phase 3+ 에서 Undo/Hint 사용률 증가 예상. BM 관점에서 적정 수준인지 확인.
5. **v2.3 주의점**: Miss 화살표가 Level 9에서 도입되므로, 첨 플레이 시 Miss 없이 진행.
