# Level Balance Document - Level 1~100

## 1. 난이도 설계 철학

### 1.1 목표
- Level 1~100까지 점진적이고 자연스러운 난이도 상승
- 플레이어가 새로운 메커니즘을 하나씩 학습할 수 있는 구조
- 하이퍼캐주얼 퍼즐 게임에 적합한 S-커브 난이도 곡선

### 1.2 고정 파라미터

| 파라미터 | 값 | 이유 |
|----------|-----|------|
| targetDensity | **0.90 ~ 0.95** | 맵이 항상 가득 찬 느낌 유지. 초반~후반 모두 동일 |
| fillerEnabled | false | Filler 없이 Main/Miss/Decoy 화살표만으로 밀도 달성 |

### 1.3 난이도 조절 파라미터

| 파라미터 | 범위 | 난이도 기여 | 설명 |
|----------|------|------------|------|
| gridSize | 4~20 | ★★★★★ | 그리드 크기. 클수록 화살표 수 증가, 공간 복잡도 상승 |
| laneCount | 2~6 | ★★★ | 풍선 레인 수. 많을수록 색상 매칭 경우의 수 증가 |
| balloonsPerLane | 1~8 | ★★★★ | 레인당 풍선 수. 많을수록 탈출 순서 파악이 어려움 |
| missArrowCount | 0~7 | ★★★ | 풍선과 매칭 안 되는 화살표. 노이즈 역할 |
| decoyArrowCount | 0~4 | ★★ | 함정 화살표. 탈출해도 풍선 안 터뜨림 |
| minBlockLength | 2~7 | ★★ | 최소 화살표 길이 |
| maxBlockLength | 3~16 | ★★★ | 최대 화살표 길이. 길수록 서로 더 많이 막힘 |
| bendingEnabled | T/F | ★★★ | 꺾이는 화살표 활성화. 탈출 경로 예측 난이도 상승 |
| bendingChance | 0~1.0 | ★★ | 꺾이는 화살표 비율 |

### 1.4 난이도 점수 산정 공식 (100점 만점)

밀도가 고정이므로 난이도 점수에서 밀도 항목 제거. 나머지 파라미터로 재분배:

```
DifficultyScore =
    GridScore       (0~35)  : (gridSize - 4) / 16 * 35
  + BalloonScore    (0~30)  : totalBalloons / 48 * 30
  + MissRatio       (0~15)  : missArrows / max(totalArrows, 1) * 60
  + DecoyScore      (0~8)   : decoyArrows * 2
  + BendingScore    (0~12)  : bendingChance * 12
```

여기서:
- `totalBalloons = laneCount * balloonsPerLane`
- `totalArrows = totalBalloons + missArrows + decoyArrows`

## 2. 난이도 곡선 설계

### 2.1 구간 정의

| 구간 | 레벨 | 이름 | 핵심 학습 목표 | 난이도 점수 |
|------|------|------|---------------|------------|
| Phase 1 | 1~10 | 튜토리얼 | 탭으로 화살표 탈출, 풍선 매칭 기본 | 5~18 |
| Phase 2 | 11~25 | 초급 | 탈출 순서 개념, 서로 막히는 화살표 | 18~32 |
| Phase 3 | 26~45 | 중급 | 꺾이는 화살표, Miss 화살표 등장 | 32~52 |
| Phase 4 | 46~65 | 중상급 | 큰 그리드, 다수 레인, Decoy 등장 | 52~68 |
| Phase 5 | 66~85 | 상급 | 큰 그리드, 복잡한 탈출 순서 | 68~85 |
| Phase 6 | 86~100 | 최상급 | 최대 규모, 모든 메커니즘 결합 | 85~96 |

**S-커브 채택 이유:**
- 초반(1~15): 완만한 상승 -> 이탈 방지, 기본 메커니즘 학습
- 중반(16~70): 가파른 상승 -> 도전 의식 자극, 새로운 요소 도입
- 후반(71~100): 다시 완만 -> 숙련자 대상, 극단적 난이도 회피

## 3. 난이도 곡선 설계 근거

### 3.1 하이퍼캐주얼 퍼즐 게임의 난이도 설계 원칙

1. **30초 규칙**: 초반 레벨은 30초 이내에 클리어 가능해야 함. gridSize 4~5, 화살표 3~5개면 달성 가능.

2. **1개씩 도입**: 새로운 메커니즘(꺾이는 화살표, Miss, Decoy 등)은 한 번에 1개만 도입하고, 최소 3~5레벨 동안 해당 메커니즘만 연습.

3. **실패 허용 구간**: 새 메커니즘 도입 직후 2~3레벨은 난이도를 살짝 낮춰 학습 시간 확보 (톱니 패턴).

4. **체감 난이도 vs 수치 난이도**: gridSize 증가는 시각적 압도감을 주므로 실제 난이도 증가보다 체감이 큼. 따라서 gridSize 증가 시 다른 파라미터는 보수적으로.

5. **이탈 방지**: Level 1~30에서 대부분의 이탈이 발생. 이 구간에서 "거의 성공할 뻔한" 실패 경험을 유도하여 재시도 의지 자극.

6. **밀도 고정 원칙**: 밀도는 항상 90~95%로 유지. 빈 공간이 적어야 맵이 "꽉 찬" 느낌을 줌. 난이도 차이는 화살표의 수, 복잡도, 메커니즘 조합으로 제어.

### 3.2 파라미터별 도입 시점 근거

| 메커니즘 | 도입 레벨 | 근거 |
|----------|----------|------|
| 기본 탭 탈출 | Level 1 | 핵심 메커니즘. 첫 레벨부터 |
| 서로 막히는 화살표 | Level 5 | 탈출 순서 개념 도입. 2개 화살표가 서로 막히는 최소 구조 |
| Miss 화살표 | Level 16 | 색상 매칭 실패 경험 -> 순서 중요성 학습 |
| 꺾이는 화살표 (Bending) | Level 26 | 직선 화살표 메커니즘을 충분히 익힌 후 도입 |
| 3개 레인 | Level 30 | 2개 레인 충분히 경험 후 확장 |
| Decoy 화살표 | Level 46 | 중급 이후, "함정" 개념 도입 |
| 4개+ 레인 | Level 55 | 복잡한 색상 매칭 |
| gridSize 16+ | Level 80 | 최상급. 대규모 퍼즐 |

### 3.3 gridSize 증가 전략

gridSize가 커지면 화살표 수가 기하급수적으로 증가하므로, 점진적으로 확대:

| gridSize | 총 셀 | 예상 화살표 수 (90% 밀도) | 도입 레벨 |
|----------|--------|-------------------------|----------|
| 4 | 16 | 3~4 | Level 1 |
| 5 | 25 | 5~6 | Level 5 |
| 6 | 36 | 7~8 | Level 11 |
| 7 | 49 | 9~11 | Level 26 |
| 8 | 64 | 12~14 | Level 35 |
| 10 | 100 | 17~20 | Level 50 |
| 12 | 144 | 24~28 | Level 65 |
| 14 | 196 | 30~35 | Level 75 |
| 16 | 256 | 38~45 | Level 85 |
| 18 | 324 | 48~55 | Level 92 |
| 20 | 400 | 58~65 | Level 98 |

### 3.4 밀도 고정 근거

- 밀도 50~70%의 맵은 빈 공간이 많아 "비어보이는" 느낌 -> 퍼즐 완성도 저하
- 밀도 90~95%는 화살표가 빽빽하게 채워져 "풀어야 할 문제"가 많다는 시각적 인상
- 초반 레벨(gridSize 4~5)도 90% 밀도면 화살표 3~5개로 충분히 쉬움
- 난이도 차별화는 gridSize/laneCount/miss/decoy/bending 조합으로 충분

## 4. 현재 파라미터로 구현 가능 여부

### 4.1 결론: **가능합니다**

현재 `GeneratorConfig`의 모든 파라미터를 레벨별로 지정하면 제안된 난이도 곡선을 구현할 수 있습니다.

### 4.2 파라미터 매핑

| 난이도 요소 | 대응 파라미터 | 제어 가능 여부 |
|------------|-------------|--------------|
| 그리드 규모 | `gridSize` | O - 직접 지정 |
| 풍선 복잡도 | `laneCount`, `balloonsPerLane` | O - 직접 지정 |
| 노이즈/함정 | `missArrowCount`, `decoyArrowCount` | O - 직접 지정 |
| 화살표 복잡도 | `minBlockLength`, `maxBlockLength` | O - 직접 지정 |
| 공간 밀도 | `targetDensity` | O - 0.90~0.95 고정 |
| 경로 복잡도 | `bendingEnabled`, `bendingChance` | O - 직접 지정 |

### 4.3 추가 고려사항

- **Filler**: `fillerEnabled=false`. 밀도 90%+는 Main/Miss/Decoy 화살표로 달성.
- **Branching**: `branchingMode`는 화살표 배치 다양성을 증가시킴. Level 30+ 권장.
- **색상 수**: 현재 6색(R,G,Y,P,B,O) 고정. 초반에는 2~3색만 사용되도록 laneCount로 간접 제어.

## 8. 구현 방법

### 8.1 레벨별 파라미터를 GeneratorConfig로 변환

각 레벨의 파라미터를 `GeneratorConfig`로 변환하여 `LevelGenerator.GenerateLevel(config)`에 전달하면 됩니다.

```csharp
// 예시: Level 50용 Config
var config = new LevelGenerator.GeneratorConfig
{
    gridSize = 10,
    laneCount = 3,
    balloonsPerLane = 4,
    missArrowCount = 3,
    decoyArrowCount = 1,
    minBlockLength = 3,
    maxBlockLength = 8,
    targetDensity = 0.90f,  // 항상 90%+
    bendingEnabled = true,
    bendingChance = 0.8f,
    fillerEnabled = false,
    branchingMode = false
};

var levelData = LevelGenerator.GenerateLevel(config);
```

### 8.2 AutoParams vs Manual Params

- **AutoParams**: `CalculateAutoParams(gridSize)` - gridSize 하나로 자동 계산. 빠른 프로토타이핑용.
- **Manual Params**: 이 문서의 레벨별 파라미터를 직접 지정. 정밀한 난이도 제어용.

**권장**: 이 문서의 파라미터를 기반으로 레벨별 Config 테이블을 만들어 사용.

### 8.3 생성 실패 대비

`GenerateLevel()`은 최대 50회 시도 후 실패할 수 있음. 높은 난이도 레벨(80+)에서는:
- 밀도를 0.02~0.03 낮춘 대체 Config 준비 (0.90 -> 0.87)
- 또는 maxBlockLength를 1~2 줄인 대체 Config 준비

## 9. 플레이테스트 권장사항

1. **Phase 전환점** (Level 10, 25, 45, 65, 85) 에서 체감 난이도 급변 여부 확인
2. **새 메커니즘 도입 레벨** (16, 26, 30, 46, 54, 69, 88) 에서 학습 곡선 확인
3. **클리어율 목표**:
   - Phase 1: 95%+ (첫 시도 클리어)
   - Phase 2: 85%+ (1~2회 시도)
   - Phase 3: 70%+ (2~3회 시도)
   - Phase 4: 55%+ (3~5회 시도)
   - Phase 5: 40%+ (5~10회 시도)
   - Phase 6: 25%+ (10회+ 시도)
4. **부스터 사용률**: Phase 4+ 에서 Undo/Hint 사용률 증가 예상. BM 관점에서 적정 수준인지 확인.
